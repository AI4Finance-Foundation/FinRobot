# 事实层文案规范

最后更新：2026-05-27（P0 事实层根治 plan 落地后）

## 一、freshness 三档标准

| age | label (zh / en) | color token | 适用 |
|-----|----------------|-------------|------|
| 0 — 5min | 近实时 / Live | `var(--accent-cyan)` | TickerHero pill |
| 5 — 30min | 延迟 / Delayed | `var(--warning)` | TickerHero pill 变黄点 |
| > 30min | 陈旧 / Stale | `var(--danger)` | TickerHero pill 变红点 |
| fetched_at 缺失 | 陈旧 / Stale | `var(--danger)` | 视为 stale，**不** fail-safe 回 fresh |

阈值常量：`ui/src/utils/format.ts`
- `FRESHNESS_WARN_SECONDS = 5 * 60`
- `FRESHNESS_DANGER_SECONDS = 30 * 60`

Helpers：`formatAge(iso)` / `freshnessColor(seconds)` / `freshnessTier(seconds)`

## 二、"LIVE" 词的边界

- 用户面显示 "LIVE / 近实时" **当且仅当** `fetched_at ≤ 5min`
- 不允许在 fetched_at 缺失 / 超过阈值时仍显示 "LIVE" 或 "近实时"
- "非 AI" / "yfinance" / "SEC 10-K" 是 **数据来源** 标签（provider 名），与 freshness label 语义不同，不能共用同一个 chip

## 三、错误状态分流

| 错误源 | HTTP status | UI view | 备注 |
|--------|------------|---------|------|
| yfinance 返回空数据 / "delisted" / 未知 ticker | 422 | `TickerNotFoundView` | 无 escape hatch，强制回搜索 |
| yfinance 429 / rate limit / 5xx / connection timeout | 502 | `ServiceDownView` | exponential backoff 30→60→120→240→300 capped |
| sidecar 未启 / CORS / Abort / network | (no HTTP) | `ServiceDownView` | 同上 |
| 其他 (500/4xx) | as-is | `ServiceDownView`（兜底） | |

判定逻辑：`ui/src/views/StockWorkspace.tsx` gate：`error instanceof FetchHttpError && error.status === 422 → NotFound; else → ServiceDown`

## 四、为什么这样规定

v1 阶段 TickerHero 和 MarketDataZone 三处都写 "LIVE"：分别想表达"近实时报价"、"live data card"、"非 AI 算出"。同一屏幕同一个词承担 3 种语义，金融用户读到 "LIVE" 默认为 streaming quote，与底层 60s 轮询 + 15min cache 不符——这是品牌可信度漏洞。

## 五、协议而非建议

- TickerHero pill label 必须用 `t('marketdata.tier.{fresh,delayed,stale}')`（locale-reactive，不允许 hardcode 字面）
- 任何新的报价 / freshness 指示器组件必须复用 `freshnessTier(seconds)` + `freshnessColor(seconds)` 两个 helper，不允许另写阈值
- Audit test `tests/audit/test_yfinance_error_mapping.py` 锁住 `_YFINANCE_SERVICE_DOWN_KEYWORDS`；删 keyword 需 reviewer 显式确认
- CLAUDE.md "工程纪律" 段有对应的一行红线
