## Track A — 数据层健壮性（D4, D5, D6）

### Task 1: D4 — 交叉校验扩展到所有 financials provider

**文件:** `finagent/engine/data/layer.py`

**现状:** `fetch()` 拿到第一个成功结果后只再试一个 provider 就 break。三个 provider 都配置时，第三个永远不参与校验。

**修改:**
- `fetch()` 对 `DataType.FINANCIALS` 不再在第二个成功后 break，而是继续迭代剩余 provider
- 每个后续成功结果都与 primary 做 `cross_validate()`，warnings 累加
- 全部 provider 尝试完或失败后才 break
- 性能兜底：最多尝试 3 个 provider（硬上限），避免配了 10 个 provider 的极端情况

**测试:** 配 3 个 mock provider，验证第三个的 discrepancy 也出现在 warnings 里。

---

### Task 2: D5 — secondary 返回空 dict 时发出告警

**文件:** `finagent/engine/data/layer.py`, `finagent/engine/data/validator.py`

**现状:** secondary provider fetch 成功但 `data={}` 时，`cross_validate()` 对每个字段都 continue，返回空 list → 静默通过。

**修改:**
- `cross_validate()` 开头检查 `if not secondary.data`，追加一条 warning：`"Secondary provider {name} returned empty data — cross-validation skipped"`
- `layer.py` 里如果 secondary `data` 为空，跳过 `cross_validate` 调用，继续尝试下一个 provider

**测试:** mock secondary 返回 `DataResult(data={})` → warnings 包含 "empty data" 提示。

---

### Task 3: D6 — compact context 加 fallback 摘要

**文件:** `finagent/engine/pipelines/base.py` — `_gather_data()`

**现状:** Step N-3 及更早的纯文本输出被替换成 `[Previous: xxx — N words, see structured_context for data]`。如果该步骤没产生 structured data，信息完全丢失。

**修改:**
- 对没有 structured_context 的步骤，占位符改为包含首 300 字符的摘要：
  `[Previous: {name} — {word_count} words] {text[:300]}...`
- 对有 structured_context 的步骤保持现状（指向 structured_context 即可）

**测试:** 4 步 pipeline，step 1 只有文本无 structured → step 4 的 prompt 里包含 step 1 的前 300 字符。

## Track B — Server + CLI 打磨（I1, I2, I3）

### Task 4: I1 — SSE 端点缓存 sub-agents

**文件:** `finagent/server.py`

**现状:** 每次 `/api/pipeline/stream/...` 请求都调 `create_sub_agents()`，重新加载 5 个 instructions markdown + 实例化 5 个 Agent。

**修改:**
- `lifespan` 里构建 `app.state.sub_agents = create_sub_agents(settings, skill_registry=registry)`
- `pipeline_stream()` 直接用 `request.app.state.sub_agents`，不再每次重建
- 如果 settings 的 model 配置改了（运行时热更新），需要重建——但当前没有热更新机制，所以不处理

**测试:** 两次 SSE 请求，用 monkeypatch 让 `create_sub_agents` 计数，验证只被调用一次。

### Task 5: I2 — SSE complete 事件不内嵌报告

**文件:** `finagent/server.py`

**现状:** `{"event": "complete", "summary": result.format_summary()[:2000]}`。

**修改:**
- complete 事件改为：
  ```json
  {"event": "complete", "ticker": "AAPL", "report_url": "/api/report/html?ticker=AAPL"}
  ```
- 不再内嵌 summary 文本。前端必须通过 `/api/report/html` 或 `/api/report/pdf` 拿完整报告。
- 保留 `report_cache` 写入逻辑不变。

**测试:** SSE 流的 complete 事件包含 `report_url`，不包含 `summary`。

### Task 6: I3 — CliProgress 重试时重新打印步骤名

**文件:** `finagent/cli.py` — `CliProgress`

**现状:** `on_step_start` 用 `nl=False` 写 `[1/5] Data Collection...`，retry 后 `on_step_end` 会输出孤立的 ` done (3.2s)`。

**修改:**
- `on_step_retry` 末尾加一个 `click.echo(f"  [{step_index}/{total}] {label}...", nl=False)` 重新打印当前步骤名，这样下一次 end 的 `done` 能跟对行
- 或者：改为每行独立输出（不用 `nl=False`），每行格式 `[1/5] Data Collection... done (3.2s)` 或 `[1/5] Data Collection... retry 1 (error)`

**测试:** mock pipeline 跑 2 步，第一步 retry 一次 → 终端输出无孤立行。

### Task 8: I6 — SDK close() 顺序修复

**文件:** `finagent/sdk.py`

**现状:** `close()` 先 `await data_layer.close()` 再 `self._loop.close()`。aiosqlite worker thread 在连接关闭后可能还有异步回调试图回 loop，触发 `RuntimeError: Event loop is closed`。

**修改:**
- `close()` 在关闭 loop 之前，先 flush：
  ```python
  if self._loop is not None and not self._loop.is_closed():
      # Give aiosqlite's worker thread time to drain pending callbacks
      self._loop.run_until_complete(asyncio.sleep(0))
      self._loop.close()
      self._loop = None
  ```
- 或者更彻底：把 `_loop.close()` 放到 `__del__` 里（带 try/except），让 GC 决定何时关。但这不如显式 flush 可控。

**测试:** 跑 SDK test suite 时加 `-W error::pytest.PytestUnhandledThreadExceptionWarning`，确认 "Event loop is closed" warning 消失。

## Track D — LBO Excel 根本修复（D3-root）

### Task 9: Pipeline 缓存 LBOInputs

**文件:** `finagent/engine/pipelines/lbo.py`, `finagent/server.py`

**现状:** LBO pipeline 的 `execute_fn` 把 `LBOResult` 写入 `structured_results["lbo_computation"]`，但 `LBOInputs` 没有缓存。server 的 Excel 导出端点因此返回 501。

**修改:**
- `pipelines/lbo.py` 的 LBO compute step 的 `execute_fn` 同时把 `LBOInputs` 存入 `structured_results["lbo_inputs"]`
- `server.py` 的 `build_report_context()` 把 `lbo_inputs` 也写入 `report_cache[ticker]["lbo_inputs"]`
- `server.py` 的 `export_excel` 端点：删除 501 分支，从 cache 取 `lbo_inputs`，传给 `generate_lbo_excel(lbo_result, lbo_inputs)`
- 如果 `lbo_inputs` 不在 cache 里（老的 cache entry），仍返回 404 + 明确说明需要重新跑 LBO pipeline

**测试:**
- 跑 LBO pipeline（TestModel）→ `report_cache` 里同时有 `lbo_result` 和 `lbo_inputs`
- `/api/export/excel/lbo/TEST` 返回 200 + xlsx content-type

## Track E — A 股国际化（第一步）

> 完整国际化是一个大 track，P5 只做最小可用的第一步：让非美股 ticker 不会系统性算错。

### Task 10: ticker 格式松绑

**文件:** `finagent/engine/data/providers/yfinance_provider.py`, `finagent/engine/compute/extractor.py`

**现状:** 所有代码假设 ticker 是美股格式（纯字母，如 AAPL）。A 股格式是 `600519.SS` 或 `000858.SZ`，港股是 `0700.HK`。

**修改:**
- yfinance provider：不做格式校验（yfinance 本身支持 `.SS`/`.SZ`/`.HK` 后缀）
- extractor：不对 ticker 格式做假设
- 检查所有 `ticker.upper()` 调用——`.SS` 后缀不应被改变
- **不做**：货币转换、交易所感知路由、非美数据源——这些留到后续

### Task 11: 税率/折扣率参数文档化

**文件:** README.md

**修改:**
- "Quickstart" 或 "Configuration" 节加一段说明：
  > Default financial assumptions (tax rate 21%, risk-free rate from US 10Y Treasury) are calibrated for US equities. For non-US markets, override via `ForecastAssumptions(tax_rate=0.196)` (SDK) or future CLI flags.
- 不做代码改动（C2 已经参数化了 tax_rate），只做文档。
