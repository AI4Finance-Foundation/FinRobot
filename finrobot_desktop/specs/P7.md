### Task 0.2: Markdown 转 HTML 渲染

**文件：** `finagent/engine/reports/html_renderer.py`

**问题：** Company Overview section 显示原始 Markdown（`## Executive Summary **Recommendation:** Sell`）。
pipeline 的 report step 输出是 Markdown 格式，模板直接插入了原始文本。

**修法：** 加 Jinja2 filter 把 Markdown 转 HTML：

```python
import re

def _markdown_to_html(text: str) -> str:
    if not text:
        return ""
    # headings
    text = re.sub(r'^### (.+)$', r'<h4 class="heading-3">\1</h4>', text, flags=re.MULTILINE)
    text = re.sub(r'^## (.+)$', r'<h3 class="heading-2">\1</h3>', text, flags=re.MULTILINE)
    # bold
    text = re.sub(r'\*\*(.+?)\*\*', r'<strong>\1</strong>', text)
    # list items
    text = re.sub(r'^- (.+)$', r'<li>\1</li>', text, flags=re.MULTILINE)
    # horizontal rule
    text = re.sub(r'^---$', r'<hr>', text, flags=re.MULTILINE)
    # table rows (| col1 | col2 |) — wrap in <pre> as fallback
    # paragraphs
    paragraphs = text.split('\n\n')
    result = []
    for p in paragraphs:
        p = p.strip()
        if p.startswith('<h') or p.startswith('<li') or p.startswith('<hr'):
            result.append(p)
        elif p:
            result.append(f'<p class="body-text">{p}</p>')
    return '\n'.join(result)

env.filters["md"] = _markdown_to_html
```

模板里所有展示 LLM 文本的地方改为 `{{ text | md | safe }}`。

## Track A — 量化回测模块

FinRobot 用 BackTrader（184 行），支持 SMA 交叉策略、自定义策略加载、Sharpe/DrawDown/Returns 分析。
FinAgent 要做得更好：**不绑死 BackTrader**，用适配器模式支持多引擎。

### Task A.1: 回测引擎抽象层

**新建：** `finagent/engine/backtest/engine.py`

```python
from abc import ABC, abstractmethod
from pydantic import BaseModel

class BacktestConfig(BaseModel):
    ticker: str
    start_date: str  # YYYY-MM-DD
    end_date: str
    strategy: str  # "sma_crossover" or custom module:ClassName
    strategy_params: dict = {}
    initial_cash: float = 100_000.0

class BacktestResult(BaseModel):
    initial_value: float
    final_value: float
    total_return: float
    sharpe_ratio: float | None = None
    max_drawdown: float | None = None
    total_trades: int = 0
    winning_trades: int = 0
    losing_trades: int = 0
    chart_base64: str | None = None  # PNG of equity curve
    warnings: list[str] = []

class BacktestEngine(ABC):
    @abstractmethod
    async def run(self, config: BacktestConfig) -> BacktestResult: ...
```

### Task A.2: BackTrader 适配器

**新建：** `finagent/engine/backtest/backtrader_adapter.py`

实现 `BacktestEngine`，内部用 `asyncio.to_thread()` 包装 BackTrader 的同步调用。
- 内置 SMA_CrossOver 策略
- 支持 `module:ClassName` 动态加载自定义策略
- 4 个分析器：SharpeRatio, DrawDown, Returns, TradeAnalyzer
- 生成 equity curve PNG → base64

**新增依赖：** `backtrader` 加到 `pyproject.toml` 的 optional dependencies：

## Track C — RAG Q&A 独立命令

FinRobot 支持 Earnings Call + SEC 10-K 的语义 RAG 问答。
FinAgent 有 BM25 RAG 但没有独立问答接口。

### Task C.1: CLI 命令 `finagent ask`

**修改：** `finagent/cli.py`

```

finagent ask AAPL "How did management discuss AI strategy in the latest filing?"
```

流程：
1. 调 SEC provider 获取 10-K（已有多 section 解析）
2. 用 BM25 RAG 检索相关 chunks（已有 BM25Index）
3. 把检索结果 + 问题传给 LLM
4. 输出 LLM 回答 + 引用来源（chunk 标签 "[Item 1A] ..."）

### Task C.2: 可选语义 RAG（embedding）

**新建：** `finagent/engine/rag/embedding_index.py`

可选功能——如果用户装了 `sentence-transformers`，用 embedding 替代 BM25：

```toml
[project.optional-dependencies]
rag = ["sentence-transformers>=2.0", "numpy>=1.24"]
```

> **决策变更（实施时）**：原 spec 写了 `chromadb>=0.4`，实际实现改为 numpy
> cosine similarity (`EmbeddingIndex` in `finagent/engine/rag/embedding_index.py`)。
>
> **原因**：
> 1. ChromaDB 是重依赖（拉入 onnxruntime、protobuf、数十个传递依赖），与 FinAgent
>    "零冗余依赖" 原则冲突
> 2. 我们的 RAG 查询集很小（单篇 10-K 的 chunks），不需要 ANN 索引——
>    numpy brute-force cosine 已足够快（<10ms）
> 3. BM25（默认）+ numpy cosine（可选）覆盖了所有实际场景
>
> **代价**：无持久化 vector store。如果未来需要跨文件大规模检索，重新评估。

接口和 BM25Index 一致（`search(query, top_k) -> list[str]`），pipeline 代码不用改。
默认用 BM25（零依赖），有 `sentence-transformers` 时自动升级。
